## Velora OS v0.11.0
### Что нового
- Текстовый редактор Plume, команда `plume [ФАЙЛ]`. Открывает файл или создаёт новый, сохраняет (`^S`) и сохраняет под другим именем (`^O`, с вопросом, если файл уже есть). Поиск без учёта регистра, в том числе для кириллицы (`^W`, следующее совпадение — `^N`), переход к строке (`^L`). Вырезать строку (`^K`, повторные `^K` добавляют строки) или выделенный текст (`^B` ставит отметку) и вставить (`^U`). Две строки подсказок внизу, справка по `^G`.
- Plume работает с UTF-8 и кириллицей (Alt+Shift переключает раскладку). Окончания строк CRLF сохраняются как были. Файл с неверным UTF-8 открывается только для чтения.
- Защита от потери изменений: `^X` при несохранённых изменениях спрашивает, сохранить ли их (Y/N, на русской раскладке Д/Н; `^C` — отмена). Если запись не удалась, редактор не закрывается.
- Логика редактора — библиотека `libc/editor` (`velora-editor`) без ввода-вывода, с 30 юнит-тестами на хосте. Экран обновляется только в изменившихся строках (решение D38).
- Консоль ядра: видимый курсор (подчёркивание), инверсия цвета (SGR 7/27), скрытие и показ курсора (`ESC[?25l`/`ESC[?25h`), очистка до конца экрана (`ESC[J`).
- Тест `boot` в QEMU: в Plume создаётся файл с кириллицей, сохраняется после вопроса при выходе, затем открывается снова, ищется строка, она вырезается, вставляется и файл сохраняется `^S`; содержимое проверяется командой `cat`.
- Тесты: 171 юнит-тест на хосте (30 новых — редактор), 90 тестов ядра, 34 проверки в `vtest`.

### Исправления
- Символ UTF-8, разорванный между двумя вызовами `write` на консоль, показывался как два U+FFFD (#28).
- `tests/qemu_run.py`: `Session.wait` после двух совпадений в незаконченной строке пропускал следующую строку вывода (#29). Для теста `boot` в `test.sh` время увеличено до 300 с.

### Известные проблемы
- В Plume нет отмены действий (undo), автоматического отступа, переноса длинных строк (строка сдвигается по горизонтали) и подсветки синтаксиса.
- Plume не следит за изменением размера экрана во время работы.
- Ограничения прошлых версий остаются (сигналов нет, одна блокировка VFS, только UEFI, нет DNS, virtio-blk не работает с QEMU 8.2 — #19).

### What's new
- The Plume text editor, the `plume [FILE]` command. It opens a file or creates a new one, saves (`^S`) and saves under another name (`^O`, with a question if the file exists). Case-insensitive search, Cyrillic included (`^W`, next match `^N`), go to a line (`^L`). Cut a line (`^K`; repeated `^K` adds lines) or the marked text (`^B` sets the mark) and paste (`^U`). Two lines of key hints at the bottom, help on `^G`.
- Plume handles UTF-8 and Cyrillic (Alt+Shift switches the layout). CRLF line ends are kept as they were. A file with invalid UTF-8 opens read-only.
- Protection against losing changes: `^X` with unsaved changes asks whether to save them (Y/N, also the Russian-layout keys; `^C` cancels). If writing fails the editor stays open.
- The editor logic is the `libc/editor` library (`velora-editor`) without I/O, with 30 host unit tests. Only changed rows of the screen are redrawn (decision D38).
- Kernel console: a visible cursor (an underline), reverse video (SGR 7/27), hiding and showing the cursor (`ESC[?25l`/`ESC[?25h`), erase to the end of the screen (`ESC[J`).
- The QEMU `boot` test creates a file with Cyrillic text in Plume, saves it after the question on exit, opens it again, searches for a line, cuts it, pastes it and saves with `^S`; `cat` checks the content.
- Tests: 171 host unit tests (30 new for the editor), 90 kernel tests, 34 checks in `vtest`.

### Fixes
- A UTF-8 character split between two `write` calls to the console was shown as two U+FFFD (#28).
- `tests/qemu_run.py`: after two matches in the unfinished last line, `Session.wait` skipped the next output line (#29). `test.sh` gives the `boot` test 300 s.

### Known issues
- Plume has no undo, auto-indent, wrapping of long lines (the line scrolls sideways) or syntax highlighting.
- Plume does not follow changes of the screen size while it runs.
- Earlier limitations remain (no signals, one VFS lock, UEFI only, no DNS, virtio-blk does not work with QEMU 8.2 — #19).
