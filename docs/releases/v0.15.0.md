## Velora OS v0.15.0
### Что нового
- USB: драйвер контроллера xHCI. Передача контроллера от BIOS, сброс, кольца команд и событий, сброс портов, адресация устройств, управляющие, массовые и прерывающие передачи (решение D44).
- USB-клавиатура (HID boot protocol): клавиши переводятся в скан-коды PS/2 и идут через тот же декодер, поэтому раскладки EN/RU, Alt+Shift и Ctrl+C работают так же, как у PS/2.
- USB-мышь (HID boot protocol): события доступны в `/dev/mouse` пакетами по 4 байта (кнопки, dx, dy, колесо).
- USB-флешки (bulk-only transport, SCSI): блочные устройства `usb0`, `usb1`, ...; разделы GPT и FAT32 монтируются в `/mnt/usb0p1` и т. д. При загрузке с `velora-usb.img` система видит свою флешку и хранит на ней журнал паники.
- Разбор дескрипторов USB, отчётов HID и команд SCSI — в крейте `velora-usb` с тестами на хосте. Параметр ядра `velora.nousb` выключает USB.
- Тесты: тесты ядра в QEMU подключают usb-kbd, usb-mouse и usb-storage; ввод с клавиатуры идёт через USB, проверяются движение и щелчок мыши, чтение и запись файлов на флешке (запись проверяется на хосте после каждой загрузки). Тест `usb` проверяет, что загрузочная флешка видна и на ней журнал паники. 187 юнит-тестов на хосте, 100 тестов ядра.

### Исправления
- Нет.

### Известные проблемы
- Не поддерживаются USB-хабы (устройства за хабом не видны) и подключение устройств после загрузки.
- Светодиоды USB-клавиатуры (Caps Lock, Num Lock) не переключаются.
- USB опрашивается раз в тик (10 мс), прерывания MSI не используются.
- Ограничения прошлых версий остаются (сигналов нет, одна блокировка VFS, только UEFI, нет DNS, virtio-blk не работает с QEMU 8.2 — #19).

---

### What's new
- USB: an xHCI host controller driver. BIOS handoff, reset, command and event rings, port reset, device addressing, control, bulk and interrupt transfers (decision D44).
- USB keyboards (HID boot protocol): keys become PS/2 scancodes and go through the same decoder, so the EN/RU layouts, Alt+Shift and Ctrl+C work as with PS/2.
- USB mice (HID boot protocol): events are available in `/dev/mouse` as 4-byte packets (buttons, dx, dy, wheel).
- USB flash drives (bulk-only transport, SCSI): block devices `usb0`, `usb1`, ...; GPT partitions and FAT32 are mounted at `/mnt/usb0p1` and so on. Booted from `velora-usb.img`, the system sees its drive and keeps the panic log there.
- USB descriptor, HID report and SCSI command handling is in the `velora-usb` crate with host tests. The `velora.nousb` kernel parameter turns USB off.
- Tests: the QEMU kernel tests attach usb-kbd, usb-mouse and usb-storage; keyboard input goes through USB, mouse movement and a click are checked, files are read and written on the drive (the write is checked on the host after each boot). The `usb` test checks that the boot drive is visible and holds the panic log. 187 host unit tests, 100 kernel tests.

### Fixes
- None.

### Known issues
- USB hubs (devices behind a hub are not seen) and devices connected after boot are not supported.
- USB keyboard LEDs (Caps Lock, Num Lock) do not change.
- USB is polled every tick (10 ms); MSI interrupts are not used.
- Earlier limitations remain (no signals, one VFS lock, UEFI only, no DNS, virtio-blk does not work with QEMU 8.2 — #19).
